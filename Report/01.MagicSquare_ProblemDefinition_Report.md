## 2. Mom Test 워크북

### 2.1 페르소나

4×4 **부분 마방진** — 빈칸(`0`) **정확히 2개**, 값 **1~16**, **10개 라인**(4행·4열·2대각선) 합 **34**를 맞추는 **학습자**(손/코드). 최근 맥락: **OO 과제**.

### 2.2 인터뷰 답변 (과거 사실)

| # | 멘토 질문 요지 | 학습자 답변 (원문) |
|---|----------------|-------------------|
| — | 지난주 OO 과제 | 「지난주 OO 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데 **대각선 하나를 빼먹어서 20분 날렸다**.」 |
| 2 | 20분 동안 반복 행동 | 「**숫자를 바꿔넣어봤어**」 |
| 3 | ‘맞다’고 본 기준 | 「**행 합만 34**」 |
| 4 | 대각선 누락 인지 계기 | 「**직접 대각선 합 적어봤어**」 |
| 5 | 대각선 적기 직전 | 「**빈칸 숫자가 또 안맞았어**」 |
| 6 | ‘안 맞다’ 근거 | 「**열합이 34가 아니었어**」 |
| 7 | 열합 불일치 직후 행동 | 「**숫자 다시 바꿔넣었어**」 |
| 8 | 두 번째 변경 시 확인 범위 | *(미응답 — 재인터뷰 권장)* |

### 2.3 표면 문제 (금지 — 제품 가설로 사용하지 않음)

- 「4×4 마방진 **대각선까지 자동 검증하는 프로그램**을 만든다」
- 「빈칸 2개 **자동으로 채워 주는 Solver**를 만든다」
- 「OO 과제용 **ECB/TDD 워크벤치**를 만든다」

### 2.4 진짜 문제 (한 문장)

4×4 부분 마방진에서 빈칸을 맞출 때 **‘맞다’고 볼 검산 기준과 순서가 흔들려** 행합만 맞다고 보고 숫자를 반복 바꿔 넣다가, 열합·대각선 불일치를 **뒤늦게** 알아차리며 **같은 시행착오에 20분 같은 시간 비용**을 쓴다.

### 2.5 Mom Test 증거 3줄

1. 「지난주 OO 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데 **대각선 하나를 빼먹어서 20분 날렸다**.」
2. 「숫자를 바꿔넣을 때 **행 합만 34** (맞다고 본 기준).」
3. 「**빈칸 숫자가 또 안맞았어** → **열합이 34가 아니었어** → **직접 대각선 합 적어봤어**.」

### 2.6 행동·판정 타임라인

```
[빈칸 채우기 시도]
    → 판정: 행합만 34 → 숫자 반복 변경 (~20분)
    → 열합 ≠ 34 → 숫자 다시 변경
    → 빈칸 불일치 → 직접 대각선 합 → 대각선 누락 인지
```

### 2.7 Mom Test 워크북 채점 (참고, 8/10)

| 체크 | 결과 |
|------|------|
| 미래 가정 없음 | ✅ |
| 과거 행동·시간·실수 구체성 | △ (Q8 미응답) |
| 진짜 문제에 솔루션名 없음 | ✅ |
| 표면/진짜 분리 | ✅ |
| 도메인(4×4, 10선, 34, 빈칸 2개) | △ (10선·1~16 명시 보강 권장) |

**재인터뷰 질문 1개:** 「열합이 34가 아니라서 숫자를 **다시** 바꿔 넣을 때, **4행·4열·2대각선 중 실제로 합을 적어 본 것**이 어디까지였나요?」

## 3. 세션 3 — 주제·R-G-I-O·성공 기준

### 3.1 주제 (한 문장, 솔루션 최소화)

**4×4 부분 마방진에서 ‘맞다’는 판정을, 행·열·대각선(10개 라인) 검산을 빠짐없이 거친 뒤에만 내릴 수 있게 한다.**

### 3.2 R-G-I-O

| | 내용 |
|---|------|
| **Role** | **학습자**(또는 학습자를 대신하는 **검증 호출자**) |
| **Goal** | 행합만으로 성급히 ‘맞음’ 처리하지 않고, **10라인 합 34**를 재현 가능하게 확인 |
| **Input** | `4×4 int[][]` — `0`(빈칸) **2개**, 그 외 `1~16`, `0` 제외 중복 없음 |
| **Output** | (a) 10라인별 합 34 충족 여부 (b) **실패 라인 식별** (c) 입력 계약 위반 시 **고정 오류** |

### 3.3 성공 기준 (Mom Test 증거 연결)

| ID | 성공 기준 | 증거 |
|----|-----------|------|
| **SC-1** | 행합만 34인 보드는 “완성/맞음”으로 **통과하지 않음** | ② 행 합만 34 |
| **SC-2** | 미충족 **라인 종류**(행/열/대각)가 결과에 명시됨 | ① 20분·③ 열→대각 |
| **SC-3** | 동일 보드에 대해 검증 결과가 **결정론적으로 재현**됨 | ③ 수동 검산의 비재현 |

### 3.4 이번 프로젝트에서 하지 않을 것 (표면 문제)

| 비포함 | 이유 |
|--------|------|
| 빈칸 2개 **자동 Solver** / `int[6]` 자동 산출 | 진짜 문제는 채우기 알고리즘이 아닌 **판정 흔들림** |
| **검증 앱·워크벤치 UI** 일괄 구축 | 세션 3은 **Rule·Command·Test Loop**만 |
| **ECB/TDD 툴체인** 제품화 | OO 맥락은 참고만 |
| “행만 맞으면 OK” **느슨한 완성 정의** | ② 증거와 충돌 |

## 4. 8계층 — 세션 3에서 만드는 것

*(Invariant·Contract·Component·UI 등은 후속 세션)*

### 4.1 Rule

| ID | Rule |
|----|------|
| R-IN-01 | 격자는 정확히 4×4 |
| R-IN-02 | `0`(빈칸)은 정확히 2개 |
| R-IN-03 | 값은 `0` 또는 `1~16`, `0` 제외 중복 없음 |
| R-VAL-01 | 마방 상수 **34** |
| R-VAL-02 | **완성** = 10라인 모두 합 34 |
| R-VAL-03 | 미충족 시 **실패 라인** 식별 가능 |

### 4.2 Command

| ID | Command |
|----|---------|
| CMD-01 | `ValidateInput` — R-IN-01~03, 고정 오류 |
| CMD-02 | `CheckTenLines` — 10라인 합·통과/실패 목록 |
| CMD-03 | `AssertComplete` — R-VAL-02만 `true` (SC-1) |

### 4.3 (Skill)

| ID | Skill |
|----|-------|
| SK-01 | `SumRow` / `SumCol` / `SumDiag` |
| SK-02 | `FirstFailingLine` — 첫 실패 라인 반환 (SC-2) |

### 4.4 Test Loop (RED 우선)

| ID | RED 시나리오 |
|----|----------------|
| TL-01 | 행합만 34 → `AssertComplete` 실패 (SC-1) |
| TL-02 | 행·열 OK, 대각 실패 → 대각 **라인 ID** 반환 (SC-2) |
| TL-03 | 동일 보드 2회 → 결과 동일 (SC-3) |
| TL-04 | 빈칸 3개 / 비4×4 / 값 17 → `ValidateInput` 고정 오류 |
